 Voici la revue complète. Méthode : sweep live de 100+ pages (build prod +
  serveur réel + sessions authentifiées, 2 rôles différents) pour détecter les
  crashes, plus relecture ciblée du code pour les flux qui ne se testent pas par
  simple chargement de page (récupération de mot de passe, notifications,
  export). Je n'ai pas pu tester les interactions purement client
  (drag-and-drop, QR MFA) faute d'outil de navigateur dans cet environnement —
  je le signale plutôt que de prétendre l'avoir fait.
 
  1. Ce qui ne fonctionne pas

 
  Fonctionnalités présentes mais désactivées faute d'identifiants externes
  (documenté dans le code, pas des bugs de logique — mais le résultat pour
  l'utilisateur est le même : ça ne marche pas) :
  - Notifications externes (email/SMS/push) : l'intention est journalisée, rien
  n'est réellement envoyé — seul l'onglet notifications in-app fonctionne.
  - Toute l'"IA" (conseiller stratégique, orchestrateur d'agents, assistant
  vocal, recherche "sémantique") est en réalité des heuristiques déterministes
  sur des données réelles — pas de vrai raisonnement/LLM, faute de clé API dans
  cette instance.

  2. Points faibles (à améliorer)
   
  - Aucun canal de livraison externe (email/SMS/push) — au-delà du mot de passe
  oublié, ça limite l'usabilité réelle à grande échelle (rappels, alertes,
  invitations).
  - Pas de vraie IA/LLM — écart entre l'ambition affichée par le cahier
  (§9/§16/§37-38/§41) et la réalité (heuristiques). Gros potentiel si une clé
  est un jour fournie.
  - Pas de temps réel — messagerie et notifications reposent sur du polling, pas
  de WebSocket/SSE.
  - Multi-tenant = registre seulement — PlatformOrganization existe mais n'isole
  pas réellement les données ; pas prêt à héberger plusieurs organisations
  indépendantes en production.
  - Pas de mode hors-ligne complet — le retry-on-reconnect existe, mais pas de
  lecture hors-ligne réelle (pas de service worker), alors que le cahier insiste
  explicitement là-dessus pour l'Afrique.
  - Aucune observabilité infra (APM, latence, disponibilité) — seul l'AuditLog
  applicatif existe ; un incident de prod pourrait passer inaperçu.

 📧 Email — Resend

  Parfait, l'envoi d'email est opérationnel de bout en bout dans le CRM (Resend
  configuré, EMAIL_ENABLED=true, sendEmail() fonctionnel).

  Pour passer en prod avec de vrais destinataires, la suite serait :
  1. Dashboard Resend → Domains → ajouter ton domaine → poser les
     enregistrements DNS (SPF/DKIM) chez ton registrar.
  2. Une fois vérifié, changer EMAIL_FROM en notifications@tondomaine.com dans
     .env et .env.production.bak.


  📱 SMS — Africa's Talking (déjà choisi dans .env, cohérent avec
  DEFAULT_PHONE_PREFIX=228 Togo)

  1. africastalking.com → crée un compte.
  2. Test immédiat : ton compte a par défaut un accès Sandbox (dashboard →
     bascule "Sandbox" en haut). Username = sandbox, une API Key sandbox est
     générée automatiquement. Les SMS sandbox ne partent pas vraiment vers un
     vrai téléphone — il faut ajouter des numéros de test simulés dans le
     dashboard sandbox.
  3. Pour la vraie prod : bascule en mode "Live", demande un Sender ID (ou
     utilise le shortcode partagé par défaut) — la demande de Sender ID dédié
     passe par une validation manuelle par Africa's Talking (peut prendre
     quelques jours).  

  AT_API_KEY=atsk_xxxxxxxx
  AT_USERNAME=sandbox        # puis ton username live une fois validé
  SMS_ENABLED=true
   
  💬 WhatsApp — Twilio (déjà choisi dans .env)

  1. twilio.com → crée un compte (crédit d'essai gratuit).
  2. Test immédiat : Console Twilio → Messaging → Try it out → Send a WhatsApp
     message → active le WhatsApp Sandbox. Tu envoies un code depuis ton propre
     WhatsApp vers un numéro Twilio fourni pour "rejoindre" le sandbox — après
     ça, Twilio peut t'envoyer des messages de test sans validation business.
  3. Console → Account → récupère Account SID et Auth Token (page d'accueil du
     dashboard).
  4. Pour la vraie prod : il faut un vrai profil WhatsApp Business approuvé par
     Meta via Twilio (Console → Messaging → Senders → WhatsApp senders) — ça
     demande une entreprise vérifiable et prend généralement plusieurs jours.

  TWILIO_ACCOUNT_SID=ACxxxxxxxx
  TWILIO_AUTH_TOKEN=xxxxxxxx
  TWILIO_WA_FROM=whatsapp:+14155238886   # numéro sandbox fourni par Twilio, à
  remplacer en prod
  WA_ENABLED=true

  ---

  Suggestion : commence par le sandbox de chaque fournisseur pour valider que le
  code (src/lib/notifications/*.ts) fonctionne de bout en bout avant de te
  lancer dans les démarches de vérification business (qui prennent du temps).
  Une fois que tu as une ou plusieurs de ces clés en main, colle-les dans .env,
  passe le *_ENABLED correspondant à true, redémarre le serveur dev, et je peux
  t'aider à tester l'envoi réel.
